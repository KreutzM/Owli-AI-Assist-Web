# Architecture

## Principle

Owli-AI Assist Web is backend-first, not backend-only.

The browser owns device interaction and privacy-preserving input preparation. The backend owns shared product policy, provider orchestration, prompts, quotas, security decisions, and generated media workflows.

## Layers

- `src/app` composes services and feature UI.
- `src/features` owns user-visible workflows and state.
- `src/core` owns platform-independent contracts, identity, sessions, and transport parsing.
- `src/platform` wraps direct browser capabilities.
- `src/shared` contains reusable, presentation-oriented building blocks.

Dependencies point inward toward `core`; `core` never imports UI or browser adapters.

## Runtime flow

1. Browser creates an anonymous installation ID.
2. Profile metadata is loaded from the backend.
3. The browser requests camera permission only after a user action.
4. A frame is resized and JPEG-compressed locally.
5. The API client obtains a short-lived web session.
6. Scene data is streamed through POST + Fetch ReadableStream SSE parsing.
7. The completed result is rendered as normal text; local TTS is optional.
8. Follow-ups reuse the scene token and original normalized image.
9. Audio-Postcards are generated by the backend; future MP4 rendering is server-side.

## State management

Use local reducers and small feature hooks. Introduce a global state library only after a documented need such as cross-route offline queues or authenticated account state. Avoid turning network responses into implicit global mutable state.

## PWA caching

The service worker caches only the immutable app shell. API responses, images, questions, answers, audio, and video are network-only and must not be placed in runtime caches by default.

## Error model

Network boundaries validate response shapes. User-facing errors are concise and recoverable. Provider details, request payloads, and secrets are never rendered or logged.
